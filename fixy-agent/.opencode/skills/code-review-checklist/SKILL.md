# 코드 리뷰 체크리스트

## 언제 쓰는가
PR 리뷰, 또는 변경을 커밋/머지하기 전 셀프 점검.

## 정확성
- [ ] 요구사항을 실제로 충족하나? 빠뜨린 케이스는?
- [ ] 엣지케이스: 빈 값·null·0·음수·경계·매우 큰 입력
- [ ] 실패 경로: 에러를 올바르게 전파/처리하나? 부분 실패 시 일관성은?
- [ ] 동시성: 경쟁 상태·재진입·순서 의존

## 일관성 (레거시 존중)
- [ ] 주변 코드의 구조·네이밍·에러 처리·스타일을 따랐나?
- [ ] 불필요하게 새 패턴/의존성을 도입하지 않았나?

## 견고성
- [ ] 리소스 정리(파일·커넥션·타이머·구독) — 누수 없나?
- [ ] 입력 검증·신뢰 경계, 타임아웃·재시도

## 보안
- [ ] 하드코딩된 시크릿·키 없나? 민감정보 로깅 없나?
- [ ] 인증/인가 확인, 인젝션(SQL/명령/경로) 방어, 사용자 입력 이스케이프

## 테스트·검증
- [ ] 변경에 대한 테스트가 있나? 핵심 경로 커버?
- [ ] 빌드·타입·린트 통과?

## 단순성
- [ ] 중복·죽은 코드·과한 추상화 없나? 더 간단히 같은 일을 할 수 있나?
- [ ] 이름이 의도를 드러내나? 주석은 "왜"를 설명하나?

## 심각도로 분류
🔴 머지 전 필수 · 🟡 고치면 좋음 · 🟢 사소. 억지 지적 금지 — 없으면 "이상 없음".
