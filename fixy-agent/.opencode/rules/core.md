# fixy 코어 규칙 (L5)

> 전 팀원이 공유하는 **불변 원칙**. 개정은 `/fixy-level-up` 의 사람 승인을 거쳐서만 한다.
> 이 파일은 opencode `instructions` 로 자동 주입된다(레포 내부) — 모든 작업의 토대.

## 1. 레거시 존중

- 기존 프로젝트는 **그 프로젝트의 구조·컨벤션·네이밍·에러 처리·스타일**을 우선 따른다.
- 명시적 요청 없이 아키텍처/패턴을 바꾸지 않는다. 주변 코드와 일관되게 작성한다.
- 일반 베스트프랙티스는 신규/빈 프로젝트에만 자유롭게 적용한다.

## 2. 생성과 검증의 분리

- 기능·리팩토링·버그 수정은 구현 후 독립 검증(`@fixy-reviewer`)을 거친다.
- 자기가 만든 코드를 자기가 승인하지 않는다. Critical/High 지적은 수정 후 1회 재검증.

## 3. 작게, 정직하게

- 변경은 작은 단위로. 테스트·타입·빌드의 초록 여부를 확인하고 보고한다.
- 못 한 것·건너뛴 것·실패한 것은 그대로 보고한다. 통과하지 않은 것을 통과했다고 말하지 않는다.

## 4. 보안 — 비협상

- 시크릿(토큰/키/비밀번호/인증서)·사내 식별자를 코드·스킬·규칙·PR·로그에 넣지 않는다.
- 학습물 공유 전 항상 시크릿 스캔을 통과해야 한다(도구가 강제하지만 1차 책임은 에이전트).
- 사용자 식별은 이름이 아니라 ID 로. 민감정보 로깅 금지.

## 5. 학습하는 동료

- 작업 전 `fixy_recall` 로 과거 학습을 먼저 떠올린다(추측·재조사 최소화).
- 받은 불만·교정은 고치는 데서 끝내지 않고 **기록**한다 — 같은 실수를 반복하지 않기 위해.
- 자가개선의 레벨 규약은 `self-improvement.md` 참조.
