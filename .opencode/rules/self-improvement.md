# 자가개선 레벨 규약

작은 개인 관찰(L1)이 쌓이면 한 단계씩 합쳐져, 결국 전 팀원이 공유하는 코어(L5)가 된다.
낮을수록 개인적·임시, 높을수록 팀 공통·영속. 승급은 항상 PR 로 공유된다.

```
   L1 에피소드 ──(유사한 게 쌓이면)──▶ L2 스킬 ──(자주 재사용되면)──▶ L3 공통 스킬
        │                                                              │
   개인/로컬                                                   (한 주제로 모이면)
        │                                                              ▼
   memory/episodes.jsonl                                    L4 팀 규칙 ──▶ L5 코어
                                                            (사람 승인)   (사람 승인)
```

## 레벨 정의

| 레벨 | 이름 | 저장 위치 | 범위 | 진입 조건 | 공유 |
|---|---|---|---|---|---|
| **L1** | 에피소드(관찰) | `memory/episodes.jsonl` | 개인/로컬 | 자동: 매 작업·불만·교정 | ❌ 로컬만 |
| **L2** | 스킬(절차) | `skills/<name>/SKILL.md` | 개인→팀 | 유사 L1 `minEpisodes`개 + 유사도 `minTagOverlap` 이상 | ✅ `fixy/skill-*` PR |
| **L3** | 공통 스킬 | `skills/` (scope: team) | 팀 공통 | L2 가 `minUses`회 이상 재사용 | ✅ PR (upstream 권장) |
| **L4** | 팀 규칙 | `rules/team-*.md` | 팀 공통 규칙 | 같은 태그 L3 가 `minSkills`개 이상 | ✅ PR + **사람 승인** |
| **L5** | 코어 헌법 | `rules/core.md` | 전 팀원 코어 | L4 안정화 | ✅ PR + **사람 승인** |

임계치는 `fixy.config.json > levels` 에서 팀마다 조정한다.

## 3중 제어 루프

| 루프 | 트리거 | 동작 | LLM |
|---|---|---|---|
| **이너** | 매 세션(session.idle) | `fixy-recorder` 가 프롬프트·신호·만진 파일을 L1 에 자동 append | 0 (결정론) |
| **아우터** | `/fixy-evolve` | `fixy_digest`(클러스터링) → `fixy_promote`(L1→L2) | 승급 판단·본문 작성만 |
| **메타** | `/fixy-level-up` | L2→L3 자동, L3→L4→L5 는 제안→승인→적용 | 규칙 초안 작성만 |

## 신호 종류 (L1)

- `complaint` — 사용자 불만/부정 ("아니", "왜 이렇게", "안돼")
- `correction` — 교정 요구 ("그게 아니라", "다시", "고쳐")
- `insight` — 재사용 가능한 깨달음/절차
- `success` — 잘 동작/감사
- `note` — 일반 작업 기록

불만·교정이 반복되는 주제일수록 우선 스킬화 대상이다 — 같은 실수를 막는 게 가장 값지다.

## 안전 게이트

1. **시크릿 스캔** — L2 작성(`fixy_promote`)·모든 공유(`fixy_share`) 전 강제. 발견 시 차단.
2. **사람 승인(HITL)** — L4(규칙)·L5(코어)는 자동 적용 금지. 항상 제안 → 승인 → 적용.
3. **개인 기록 비공유** — L1 에피소드(`episodes.jsonl`)는 `.gitignore` 로 공유되지 않는다. 공유되는 건 L2+ 스킬·규칙뿐.

## 스킬(SKILL.md) 작성 기준

- `name`: kebab-case, 소문자 영숫자.
- `description`: 1~2문장. "언제 쓰는지"를 분명히 (목록·검색에 노출됨).
- 본문: **다음에 그대로 따라 할 수 있을 만큼 구체적인 단계별 절차/런북**. 증상→원인→해결→예방 형태가 좋다.
- 레포 고유·일회성 맥락은 스킬로 만들지 않는다(노이즈). 재사용 가능성이 핵심.
